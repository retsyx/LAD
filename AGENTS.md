# LAD project instructions

## General

- This project is in early development. There is no need for backward compatibility with prior revisions of the software. This remains true as long as this instruction is in this file. When the software is more mature, this instruction will be replaced with an instruction to ensure backward compatibility between software revisions.

## Naming

- Use **Project** internally for a LAD document and its state and lifecycle. Apply this consistently to source filenames, types, data structures, functions, properties, variables, tests, preference keys, and scene/restoration identifiers. Do not introduce interchangeable `Design` names for these concepts.
- Use **Design** in all app-owned UI referring to the same document or CAD artifact, including menus, labels, dialogs, help, accessibility text, progress, status, and errors. Translate internal Project terminology at the UI boundary rather than exposing internal names directly.
- This naming rule does not rename externally owned SDK/API identifiers, externally required file/schema/protocol names, user-authored content, or the ordinary verb “design.” Existing app-owned identifiers and persisted keys are not exceptions. Keep the `.lad` suffix and the `project.json` archive entry.

## UI

- Refer to the CAD artifact as a design in app-owned UI, including loading/progress, fit/rebuild/details actions, and errors. Reserve model for the Codex/LLM selector and established technical terms such as KiCad component 3D model libraries.
- Call LAD documents designs in all app-owned UI, including menus, dialogs, help, accessibility labels, status, and errors.
- Don't state with labels or prompts the default/obvious/expected behavior in the UI.
- Keep viewport mouse and keyboard control instructions in the dedicated nonmodal LAD Help window, opened from Help → LAD Help (⌘?). Reuse one help window, keep it out of Project state and session restoration, and support normal native close/reopen behavior. Settings contains configuration rather than the viewport controls guide.
- Show each version's custom name, or `vN` from its history position by default, in the version selector. Allow inline naming in that dropdown without selecting, rebuilding, or changing the design title. Save version names in the `.lad` archive; show only version names in the list.
- Keep transient save and rename feedback outside the header's sizing flow, using the existing padding. Feedback appearing, changing or disappearing must not shift the design name or resize the workspace; retain complete errors in help and accessibility text.
- Keep Parts, Measurements and Design as independent vertically resizable sections of the same left panel, with draggable horizontal dividers and separate scrolling. Show Measurements for a selection and Design for an existing CAD design. The expanded CadQuery program fills the Design section's remaining height and full width, with both scroll directions available for complete long lines; do not cap its height or nest it inside a shared vertical scroll area. Omit the redundant design title and do not provide a details-visibility toggle.
- All LAD branding icons (application, project documents, and the iCloud folder badge) must match the window header: the gold `cube.transparent.fill` symbol with light weight and `Palette.accent` color. Do not use an alternate cube or letter emblem.
- Let macOS supply `.lad` file icons from the app's document-type registration; never write per-document custom-icon metadata. For the ordinary iCloud LAD folder, apply the custom icon only when Finder's persistent custom-icon flag is absent, preserving existing user icons across launches. Serialize this folder-only AppKit work on the main actor after file coordination, without blocking autosave.
- Keep ambient viewport illumination and attach the directional key/fill lights to the camera, with the main light above-right and fill above-left. Their directions must stay fixed relative to the view through orbit, pan, zoom, and projection changes; highlights should respond naturally to curved surface normals.
- Shade preview faces with finite, unit, outward normals from the exact OpenCascade face surfaces at their triangulation UV nodes, respecting face orientation and locations. Triangle-averaged lighting normals create splotchy highlights on curved blends. Preserve hard boundaries and the existing mesh/edge positions; keep lighting normals derived and session-only, separate from geometric triangle-plane normals used for edge occlusion.
- Prepare viewport drawing resources asynchronously before revealing a newly loaded model. Keep pending preparation safe across model replacement and view teardown, and avoid reassigning materials or requesting redraws for unchanged display state.
- Wake SceneKit playback for bounded redraw bursts after camera, material, visibility, highlight, layout, and activation changes; pause again when idle and cancel pending redraw tasks on detachment. A paused Metal view can ignore AppKit's `needsDisplay` flag alone. Verify fresh live-window frames after idle as well as independent render captures when changing rendering lifecycle behavior.
- End viewport redraw bursts only after a frame for the latest requested state has rendered and input has become quiet. A fixed timer can expire before a cold display link produces a frame. Keep continuous rendering confined to these bursts, preserve external render delegates, and recover after app activation, display changes, and system/display wake.
- Multipass highlight techniques complete through a geometry-free final `DRAW_NODE` marker: stamp the redraw generation in `updateAtTime` and acknowledge it only at the final marker, ignoring sporadic intermediate native `didRenderScene` callbacks. Exclude the marker from base drawing and remove its renderer delegate from independent capture clones. Never give the marker geometry or bounds that change automatic camera clipping.
- Drive mouse orbit and pan from consecutive cursor positions, including input events whose delta fields are zero. Keep right-click separate from right-drag with a small movement threshold; clear pending navigation gestures on window deactivation or detachment.
- Keep input handling fast on real assemblies: commit camera changes without animation, avoid whole-scene flushes for every movement, snapshot projection math once per camera state, and avoid duplicate polyline projections. Query the nearest surface when all parts are visible, retain hidden-part filtering, and defer face hits until vertex/edge picking needs them. Measure navigation-to-render latency and cold/warm picking with a representative preview when changing these paths.
- Traverse native OCP indexed topology maps through explicit bounded indices, rather than Python's sequence protocol, in worker extraction. Repeated native iterator-termination exceptions can dominate preparation on assemblies with thousands of faces. Preserve CadQuery's native subshape order, locations, orientations and degenerate-edge filtering so feature identities and measurements remain unchanged; keep optimizations local to LAD without patching the shared CAD runtime.
- Reuse exact native integrals for a feature's measure and centroid, and each part's analytic bounds for whole-design bounds and meshing deflection. Share final validation measurements only through the explicit single-use handoff to that build's preview; never retain statistics on mutable geometry or across builds. Preserve native wire-adaptor integration for perimeters rather than substituting edge-length sums, which differ for some trimmed or singular wires. Keep all preview measurements analytic and independent of display triangulation.

## Codex file context

- CadQuery/OCP Python programs are the only design-construction interface. Do not reintroduce feature-node graph generation, schema fields, validation, or execution. Programs assign their final geometry to `result`.
- Never inline source or design file contents in a Codex prompt. This includes attached files, historical source snapshots, and the current model's saved program.
- Support multiple user image attachments through the composer attach button, image-file or image-data drop, and native image paste. Show rounded thumbnails above the prompt with an overlapping circular remove button; retain images in saved chat and offer full previews. Decode thumbnails without blocking typing. Keep plain text paste and nonimage file/folder drops as text/path insertion. Extract saved images to private local files as needed for previews and Codex; send current attached images as typed `localImage` path inputs on both new turns and acknowledged steering, never base64 or file bytes embedded in prompt text. Retain binary image bytes once in the shared ZIP asset table across drafts, queue and conversation; original paths are provenance, not required dependencies.
- Send file references and brief metadata instead. Codex may inspect referenced inputs as needed and write programs and external-tool outputs in its private task workspace. Keep original inputs unchanged.
- Keep complete source snapshots and CAD assets locally for portable project save/load. Make saved snapshots available as local referenced files so reopening a project does not require the original paths to exist.
- Do not truncate source files or substitute guessed geometry to satisfy prompt limits. Keep the initial request bounded independently of referenced file size.
- Preserve this behavior with regression tests. Do not reintroduce full-file prompt embedding as a workaround.

## Agent CAD tools and audit

- Connect LAD's per-task MCP server by default on each Codex invocation, without changing global Codex configuration. Expose the configured runtime, build, exact topology inspection, measurements, validation, offscreen rendering, live viewport capture, STEP export and external geometry import. Give Codex instructions for the complete installed CadQuery/OCP APIs and an iterative build/inspect/measure/render workflow before returning a final design. Reuse matching validated native geometry for final commit instead of rebuilding it.
- Keep Codex's writable scope in its private task workspace, with network access for optional modeling dependencies and a local environment when needed. Do not modify the shared CAD runtime, original source files or global settings. Keep replay programs in the existing worker sandbox; provide imported assets as `imported_assets[id]`. External STEP/BREP and closed STL/OBJ inputs must validate as solids; disclose that mesh imports produce faceted BRep geometry, not recovered analytic surfaces.
- Let Codex decide whether PCB conversion is needed. Expose the existing KiCad converter as `lad_convert_kicad`, returning a temporary workspace STEP path with provenance, diagnostics and component coverage only. Never intercept chat requests with PCB/STEP keyword routing or automatically import/commit conversion results. Codex may call `lad_import` separately for a required converted external reference.
- Instruct Codex to use `lad_import` only for pre-existing external/reference geometry and faithful format conversions of user-provided inputs, including KiCad boards. Never import geometry the agent creates or modifies as part of the project, including LAD STEP exports and project-generated SDF/mesh outputs. Generated geometry belongs in the complete replayable CAD program, not a frozen imported asset. External tools remain available for analysis and prototyping.
- Preserve exact required imported reference bytes once in the shared archive asset table. Record input provenance and dependency descriptions when supplied. Keep all generated previews, topology, screenshots, BREP caches and STEP exports temporary. A conversion alone must not register or persist an input asset.
- Save per-task model/effort, timestamps, tool/command inputs and outputs, statuses, durations and exact CAD candidate/producer source snapshots. Deduplicate these source files against saved programs and attachments in the existing hash asset table. Capture public execution events only, omit private reasoning and final-response JSON, and strip derived media payloads from CLI events. Never put audit outputs or source snapshots into later prompts automatically. Cancellation, errors and interrupted sessions must retain accurate outcomes.
- Keep the existing default UI layout unchanged. Tool Activity is an optional, per-window nonmodal pane, hidden by default and never restored visible. Open it only through its toggle; keep its observation and window ownership isolated per design.
- Let AppKit own the movable, resizable Tool Activity panel's frame and size limits. Disable automatic hosting-view sizing propagation and autoresize its content within the native frame; log and image layout changes must not reposition or resize the window. Assemble complete activity transcripts and source text for Copy actions only when pressed, never while measuring or moving the pane.
- Keep Tool Activity independently movable as a standalone floating panel, without native parent/child window attachment. Track its owning design window logically for close and minimize/restore handling; moving either window must not reposition the other. Programmatic frame tests do not verify server-side title-bar dragging: check live mouse movement separately and report any automation limitation accurately.
- Show the exact PNG returned by `lad_render` and `lad_screenshot` inside that call's expanded Tool Activity result, keyed by task and scoped event identity. Decode images only for expanded results and keep their encoded bytes in a bounded session cache after the private task workspace is removed. Do not provide a separate Agent Progress pane or toggle, retain speculative geometry for a visual gallery, create additional renders, or save derived tool screenshots into `.lad` archives or later prompts. Archived or evicted results may report that their temporary preview is unavailable.
- Keep all seven `lad_render` camera presets and allow explicit yaw/elevation/roll or world-space camera position/target. Define zoom as a positive magnification relative to automatic fit (or the explicit base camera pose), with 1 unchanged, greater than 1 closer and less than 1 wider. Perspective zoom dollies toward the target; orthographic zoom changes scale while retaining the base camera position. Validate finite, nondegenerate camera inputs, return the effective pose with the image, and keep these controls confined to independent renders without moving the live viewport or changing per-design view settings.

## Project storage

- LAD is a multi-window app. New Design opens an empty independent window and leaves existing designs open. Start with no geometry, revisions, chat messages, sample prompts, or CAD worker; retain normal autosaving and per-design settings. Keep different designs' document state, conversation, workers, viewport, model/reasoning selection, and autosave identity separate. Route menu commands to the active design; opening an already-open file focuses its window. Dropping a `.lad` file on a window loads it into that receiving window after validating the incoming file and flushing the outgoing design, except in the chat editor. Dropping image files or image data in the composer attaches images. Every other file or folder dropped in the composer inserts its local path, never its contents, and never replaces the current design. Multiple windows viewing the same file share its document state and one autosave writer. Flush/cancel a design only when its last view closes, and save every open design before quitting. Only the active design updates the app's recent-design preference.
- Save New opens a save dialog and writes a separate design identity with only the latest validated model and its matching user prompt/final response, plus required assets and model organization. Preserve the open design and its full autosaved history; never replace it through Save New. Save Design As retains full history.
- Save complete projects automatically in iCloud Drive/LAD, using the design title generated by Codex for the filename and a stable project identity to prevent collisions.
- Keep successful saving silent. Show a save status only while changes are pending or saving has failed.
- Keep File → Open Recent as a persistent, bounded list of LAD file references, routing selections through normal multi-window opening. Record successful opens, initial saves, explicit copies, and filename changes; replace renamed paths and skip unchanged autosaves so Clear Menu remains cleared. Keep this menu history separate from last-session restoration.
- Save projection mode, rendering mode, and grid visibility per design, autosave changes from their controls, and restore them when opening that `.lad` file. Retain these options in Save New and full copies. New designs start with perspective projection, edges rendering, and the grid visible; never inherit another design's view choices.
- Allow clicking the header filename to rename the project inline, with Return to apply. Escape, clicking outside the name field (including empty viewport space), losing focus or leaving the window cancel without renaming. Outside clicks must still reach their original controls. Rename its on-disk `.lad` file through the coordinated autosave writer, preserving project identity and avoiding filename collisions. Retain a user-chosen project name across model revisions and Codex refinements.
- Save `.lad` files as ZIP-compressed archives while keeping the `.lad` suffix. Compress the complete asset manifest and retain the existing content deduplication and rebuildable model recipes.
- Preserve the old local session as a migration backup, and never overwrite an unrelated project because its title matches.
- Store each distinct source file, imported STEP asset, and generated program once per project, addressed by its content hash; revisions and attachments reference those shared assets.
- Save generated models as their complete CAD programs and required input assets. Never embed generated STEP outputs, native BREP caches, preview meshes, triangles, or sampled edges in project files.
- Rebuild a revision from its saved modeling instructions when first displayed. Reuse session previews and native geometry for fast history navigation; create STEP only on export. Keep part identities, hierarchy, visibility, and the creation runtime versions as persistent metadata.
- Feature topology, face/edge display mappings, and measurement reports are derived session data. Rebuild them with the native geometry; never serialize them in `.lad` files.

## Parts hierarchy

- Use a single outlined cube for the Parts pane header, matching individual part icons. Represent groups with the outlined three-cube icon (two below, one centered above), in muted gray or selection gold. Use its plus-badge variant for the new-folder button; preserve disclosure chevrons, single-cube part icons, and partial-selection badges.
- Select whole parts and folders only through the parts tree. Viewport left-click toggles native vertices, edges/curves, and faces, preserving selection order. Mark their owning parts and ancestor folders as partially selected in the tree without treating them as whole-part measurement selections. Right-click opens the context menu without changing selection. Double-click empty viewport space, Escape, and Deselect All clear both part and feature selections.
- Preview the clickable feature under the mouse with a transient hover highlight, using the same vertex/edge/face picker and occlusion rules as clicking. Hover never changes selection or measurements. Use the same gold for selected features and selected whole parts, with a softer hover treatment; selected styling takes precedence. Cache projected topology and bound inactive hover resources. Clear stale hover on exit, camera changes, hidden geometry, model replacement, or window deactivation.
- Render ordinary CAD edges as cached, depth-tested GPU-expanded strokes with a consistent width in screen points, including Retina and offscreen captures. Keep ordinary edges dark and legible; hovered edges have a thicker pale-gold core and halo, and selected edges have a wider gold core with a contrasting dark outline. Reuse geometry and drawing resources during navigation. Keep grid guides thin and separate from selectable CAD strokes.
- Derive displayed edge polylines from the same OpenCascade triangulation boundary nodes as their adjacent faces, retaining the closing segment of closed curves. Independent coarse curve sampling puts chords inside curved surfaces and breaks depth-tested outlines. Preserve native edge identity/ownership and the global segment budget; do not decimate individual curves or increase depth bias to hide this mismatch.
- When expanding ordinary depth-tested strokes in screen space, extend segment caps along the projected edge's depth tangent as well as its screen tangent. Flattening the depth of extended endpoints causes repeated self-occlusion on oblique surfaces. Verify uniform strokes on a tilted surface and retain occlusion by nearer geometry.
- Ordinary depth-tested edge ribbons use their adjacent geometric mesh triangle planes, cached once per preview and isolated by solid owner; smoothed lighting normals are unsuitable.
- Render highlights in two stages. First shade highlighted faces and parts in their highlight color with the rest of the geometry rendered normally. Then draw a viewport overlay without geometry occlusion checks: vertices and edges/curves remain visible through nearer geometry, while faces and parts contribute only the outline of their projected coverage, never their full wireframe or triangulation edges. Keep screen-point core/halo widths, round joins/caps, selected-over-hover precedence, prepared resource reuse, and independent capture targets. Verify hidden selected features, projected silhouettes of curved and faceted geometry, both projections, different zooms, and Retina widths.
- Only solid faces write ordinary visibility depth. Draw ordinary edges, grid guides and feature decorations in a separate read-only depth pass, and keep highlight overlay masks independent of scene depth. Leave ordinary technique depth comparison defaults to SceneKit so reverse-Z clearing and testing remain consistent. Regression fixtures must include ordinary edge ink beneath highlights, as in the live design.
- In translucent rendering, resolve solid visibility depth separately from face color and retain it for ordinary decoration occlusion. Composite transparent faces with commutative GPU color/alpha accumulation and multiplicative transmittance, then resolve over the scene background. Native dual-layer or source-over object sorting is insufficient for concave CAD shells and overlapping assemblies: small orbits must not cause parts to change apparent opacity when their submission order changes. Keep accumulation independent of depth rejection, preserve PBR shading, and reuse drawing resources without per-frame CPU geometry sorting. Verify nonempty rendered pixels, solid and triangle order permutations, small camera sweeps in both projections, and a representative concave assembly with enclosed parts; fixed-angle nested boxes alone do not cover this failure.
- Fade complete physically based face output with premultiplied fragment RGBA, including specular reflections; native PBR material transparency preserves glasslike reflections that can appear opaque. Let the explicit compositing passes own blending instead of SceneKit's transparent-object queue, and retain an explicit full-opacity fragment variant so mode changes restore complete opaque shading. Resolve face color, background, decorations, and final gold highlights in the final compositor; avoid an intermediate custom-quad result followed by native MSAA drawing into the same color target. Copy the compositing mode and independent targets for captures. Test rendered production PBR faces with bright highlights and enclosed colored geometry, including background preservation and returning to opaque modes; constant-lighting fixtures alone do not verify this path.
- Highlight vertices with modest circular markers in screen points (7-point hover core, 9-point selected core), using the same pale-gold hover halo and gold selection with a dark outline as edges. Expand projected vertex centers into complete circles in the unoccluded highlight overlay. Keep picking occlusion rules and its generous hit area, preserve selection precedence, and reuse prepared geometry across hover, selection, zoom, and projection changes.
- Show measurements automatically for selections: exact topology properties for individual features and part totals; native OpenCascade minimum distance and closest points for pairs; coordinates, axis deltas, supported analytic angles, radii, lengths, areas, volumes, bounds, and three-vertex triangle measurements as applicable. Do not infer a constant radius/normal for general curved geometry or mass without material density. Keep native measurements asynchronous, cancel stale results, and do not interrupt a CAD build to measure.
- Offer Export STEP in the parts context menu for the currently selected physical parts, including selected folders' descendants. Export only that subset with original CAD coordinates; never reuse full-design STEP bytes for a subset. Hidden parts may still be selected and exported from the tree.
- Parts and folders offer a Color picker in their context menu, with curated swatches, a full native picker, and recent colors stored per design. Position the native macOS color panel beside the swatch popover, keep it within the visible screen, and dismiss it with the popover. Apply colors to individual stable part identities, expand folders to their physical parts, honor multiple selection, and retain colors across save/load, history, hierarchy edits, and matching Codex refinements. Color changes must reuse preview geometry and keep selection feedback distinct.
- Codex supplies a named parts hierarchy with stable `lad_id` metadata. Preserve part identities across refinements.
- User-created folders, renamed labels, and moved items are authoritative. Add new parts to suitable folders without relocating existing user-arranged items unless explicitly requested.
- Keep hierarchy edits, visibility, and each folder's expanded/collapsed state with project revisions. Preserve folder state across rename, move, regeneration, and matching Codex refinements. Hiding parts changes only the preview, never the exported STEP geometry.

## Conversation feedback

- Snapshot selected whole parts and ordered vertices, edges and faces when a request is submitted. Include stable part IDs, names and hierarchy paths, the originating revision, and compact native geometric anchors as request intent. Preserve that snapshot through queue edits, reordering, save/load, dispatch, repairs and acknowledged same-turn steering; later live selections must never replace it. Send local selection/origin recipe/input file references to Codex, never embed their file contents. Native feature indices belong only to their originating geometry: reconcile older selections using stable IDs, anchors and exact inspection, and ask about ambiguous targets rather than guessing. Retain selected-target intent with user messages and queued requests, while keeping complete topology, polylines and display caches derived and session-only.
- Queue follow-up submissions while a design request is running, preserving their order, source snapshots, and captured model/effort choices. Start exactly one next item only after the preceding request has validated and committed. Edit queued requests in the main composer with its attachment and model/reasoning controls; restore the original unsent draft, attachments and choices after saving or canceling the edit. Keep the queue blocked while editing and keep temporary edits separate from the saved unsent draft. Allow removal and handle-only drag reordering above the composer. Vertically flip the queued send-now arrow and use the same muted color as the adjacent controls. Keep pending items and unsent drafts in the project archive with shared source assets; reopening, Stop and failure leave the queue paused until resumed.
- Send a queued item immediately only through acknowledged same-turn Codex `turn/steer`, without interrupting or spawning a parallel design task. Keep it queued until acknowledgement; retain it on rejection and do not silently retry ambiguous delivery. Disable this action outside an active Codex turn, preserve accepted supplemental chat/audit links, and handle completion/edit/send races without duplicates or dropped requests.
- Request a short opening plan from Codex and concise progress updates for substantial work. Display actual user-facing commentary as it arrives, retaining it in the saved conversation.
- Keep final CAD JSON, tool output, source file contents, and private reasoning out of progress messages. Announce completion only after the CAD worker validates the model; summarize failures and cancellation accurately.
- Do not impose an elapsed-time limit on Codex design requests. Keep Stop/cancellation responsive, including forcefully stopping a process that ignores termination.

## Codex model selection

- Discover the Codex executable automatically, preferring the installed ChatGPT/Codex app's bundled CLI before standalone command locations and VS Code extension fallbacks. Support both the app's `codex-cli/bin/codex` launcher layout and the earlier `Resources/codex` layout. Do not expose executable-path editing in Settings or direct users there to choose a Codex binary.
- Check Codex health in the background when its native Settings window opens or reopens, or LAD becomes active while that window is visible. Use the same resolved executable as design requests. Restrict health traffic to app-server initialization, `account/read` without token refresh, and `account/rateLimits/read`; never create a thread, start an inference turn, prompt an agent, or launch CAD work to check the connection. Keep healthy and unknown states silent, including their initial checks. Show a Codex section only for a specific installation, sign-in, connection, usage-limit, or spending-limit problem, with Check again and setup help. Do not describe transport errors or timeouts as missing sign-in. Use brief health-specific caches, coalesce simultaneous checks, and cancel the Settings window's pending observation on close or detachment without canceling another active consumer. Never expose account identity or credentials in the UI, diagnostics, or preferences.
- Keep model and reasoning selection together in the composer, with model first. Populate model names and supported reasoning levels from the installed Codex catalog rather than a hard-coded model list.
- Model and reasoning selection, including custom model IDs, belongs exclusively in the chat composer. Do not expose model selection in Settings.
- Store the model, reasoning level, and remembered reasoning preferences per model in each `.lad` project. Restore these choices when opening that file; do not use app-global preferences or inherit another project's selections. Initialize a new project's selection from the installed Codex configuration, then retain the explicit choice in the project.
- Reconcile unsupported reasoning levels when switching models. Apply the captured model/effort pair to new requests and their repair attempts.
- Show both model and reasoning level in the selector and running Codex task status. Keep the running status tied to the pair captured for that task, even when the selector changes for a later request.

## Restarting LAD

- Restart LAD after completing app changes when requested in the session. If LAD prompts to save during the restart, choose not to save.
